# הדרך הקלה — מערכת הזמנות שולחנית למסעדה

מערכת הזמנות בזמן אמת למסעדה: כל סועד סורק QR/NFC של השולחן ופותח את התפריט
בנייד שלו, כל מה שמוסיפים לעגלה מסונכרן בזמן אמת אל "טאבלט המאסטר" שעל
השולחן, ורק דרך הטאבלט הזה אפשר לשלוח מנות בפועל למטבח. יש תמיכה בפייר
(שליחה מתוזמנת של מנות לפי קורס — ראשונות/עיקריות/קינוחים) ובביטול מנה כל
עוד המטבח לא התחיל להכין אותה.

## הרצה

```bash
npm install
npm start
```

השרת עולה על `http://localhost:3000`.

- `/` — דף בית עם רשימת השולחנות, קוד QR לכל שולחן, וקישור ישיר לטאבלט המאסטר.
- `/t/:token` — תפריט הסועד (מה שנפתח לאחר סריקת ה-QR/NFC של השולחן).
- `/master/:token` — טאבלט המאסטר של השולחן.
- `/kitchen` — עמדת המטבח (כל המנות — ראשונות/עיקריות/קינוחים — מכל השולחנות).
- `/bar` — עמדת הבר (רק משקאות, מכל השולחנות).
- `/waiters` — מסך המלצרים של המטבח (מנות שסומנו כמוכנות, עם התראה קולית).
- `/waiters/bar` — מסך המלצרים של הבר (משקאות שסומנו כמוכנים, עם התראה קולית).

בסביבת פיתוח בלי מדפסות NFC/QR פיזיות — פותחים את `/` ולוחצים על הקישורים של
כל שולחן בכמה טאבים כדי לדמות מספר מכשירים.

## ארכיטקטורה

- **Backend**: Node.js + Express + Socket.io. State מוחזק בזיכרון (`server/store.js`)
  ונשמר ל-`data/store.json` בכל שינוי, כך שהפעלה מחדש של השרת לא מאבדת הזמנות פתוחות.
- **מודל נתונים** (`server/models.js`): שולחנות (`tables`), פריטי תפריט
  (`menuItems`), הזמנה פתוחה לשולחן (`sessions` — נוצרת אוטומטית בסריקה
  הראשונה ונסגרת ע"י הטאבלט המאסטר), סועדים (`diners`), ופריטי הזמנה
  (`orderItems`) עם מכונת מצבים:
  `in_cart → sent → preparing → ready → served`, וכן `cancelled` (רק
  מ-`sent`).
- **זמן אמת**: כל הצדדים (נייד סועד / טאבלט מאסטר / מסך מטבח) מחוברים ב-
  Socket.io ל"חדר" של ה-session; המטבח גם מחובר לחדר `kitchen` גלובלי שמרכז
  את כל השולחנות. כל שינוי במצב משדר מחדש את המצב המלא לכל הצדדים — מציאה
  פשוטה וחסינת-שגיאות למערכת בקנה מידה של מסעדה בודדת.
- **שתי עמדות הכנה**: כל פריט תפריט משויך לעמדה לפי הקורס שלו —
  `COURSE_STATION` ב-`public/shared/labels.js` ממפה `drink → bar` ואת
  `starter/main/dessert → kitchen`. עמדות המטבח/בר ומסכי המלצרים שלהן
  מאזינים לאותו broadcast (`kitchen:state`) ומסננים בצד הלקוח לפי המיפוי
  הזה — כך שאין צורך בחיבורי socket נפרדים, רק ב-HTML שונה לכל עמדה.
- **Frontend**: HTML/CSS/JS פשוטים (ללא build step), RTL מלא. חוויות נפרדות
  תחת `public/diner`, `public/master`, `public/kitchen` (גם משמש את `/bar`),
  `public/waiters` (גם משמש את `/waiters/bar`), ודף בית תחת `public/home`.

## זרימת השימוש

1. סועד סורק QR/NFC של השולחן → נפתח `/t/:token` → אם זו הפעם הראשונה
   שסורקים את השולחן, נוצרת session חדשה ("הזמנה פתוחה") אוטומטית.
2. הסועד ממלא שם ומתווסף כ-diner ל-session. הזהות נשמרת ב-localStorage כך
   שרענון הדף לא יוצר סועד כפול.
3. הסועד מוסיף מנות לעגלה — הפריט נכנס במצב `in_cart` ומופיע בזמן אמת גם
   אצל שאר הסועדים בשולחן וגם בטאבלט המאסטר.
   - **הסרה מהעגלה** (לפני שנשלח למטבח): גם הסועד שהוסיף (מהנייד שלו) וגם
     הטאבלט המאסטר יכולים להסיר פריט מה-`in_cart`. זו הסרה "רכה" — הפריט
     עובר למצב `removed` ולא נעלם, כך שהוא ממשיך להופיע בסעיף "הוסרו
     מהעגלה" גם בטאבלט המאסטר וגם בנייד של מי שהוסיף אותו במקור (גם אם
     המאסטר, ולא הסועד, הוא זה שהסיר).
4. **רק** הטאבלט המאסטר יכול לשלוח מנות בפועל למטבח:
   - שליחה בודדת של פריט.
   - שליחה מרובה של פריטים מסומנים.
   - **פייר לפי קורס** — כפתור "🔥 שלח את כל ה[קורס]" ששולח בבת אחת את כל
     פריטי ה-`in_cart` מאותו קורס (למשל: לשלוח את כל הראשונות עכשיו, ואת
     העיקריות רק כשרוצים — כדי לתזמן שהעיקריות יגיעו אחרי הראשונות).
5. מסך המטבח מציג את כל השולחנות עם המנות שנשלחו. הטבח מסמן "התחלת הכנה"
   (`preparing`) ואז "מוכן" (`ready`).
6. **ביטול מנה**: כפתור הביטול בטאבלט המאסטר מוצג אך ורק כשהמנה עדיין
   במצב `sent` (נשלחה אך המטבח לא התחיל להכין). ברגע שהטבח לוחץ "התחלת
   הכנה" הכפתור נעלם — לא ניתן לבטל מנה שכבר בהכנה.
7. **מסך המלצרים** (`/waiters`) מרכז מכל השולחנות רק מנות שסומנו `ready` —
   עם מספר שולחן בולט, זמן המתנה (מודגש באדום אחרי 3 דקות), והתראה קולית
   (מבוססת Web Audio, בלי קובץ שמע חיצוני) כשמנה חדשה מוכנה. עד שהמלצר לא
   לוחץ שם "✅ לקחתי, בדרך לשולחן" — גם הטאבלט המאסטר וגם נייד הסועד עדיין
   מציגים את המנה כ"בהכנה" ולא חושפים שהיא כבר מוכנה. ברגע שהמלצר לוחץ,
   המנה עוברת ל-`served`, והטאבלט המאסטר ("🍽️ הוגש — בתאבון!") ונייד
   הסועד ("🍽️ בתאבון!") מתעדכנים מיידית.
   - בנייד הסועד, שלושת המצבים `sent`/`preparing`/`ready` תמיד מוצגים
     ביחד כ"בהכנה" עם הודעה מתחלפת (👨‍🍳🔥✨) כל כמה שניות — כדי שהסועד לא
     "יידע" שהמנה כבר מוכנה לפני שהיא בפועל בדרך אליו.
8. **פיצול חשבון וטיפ אישי**: בכרטיסיית "עגלת השולחן" בנייד שלו, כל סועד
   רואה כרטיס "החשבון שלי" — סכום המנות שהוא עצמו הזמין (לא כל השולחן),
   ובוחר טיפ באמצעות כפתורי אחוזים מהירים (10/12/15/20%) או סכום מותאם
   אישית בש"ח. הטאבלט המאסטר מציג במקביל "פירוט חשבון לפי סועד" — סכום,
   טיפ וסה"כ לכל אחד מהסועדים, וכן סה"כ לשולחן כולל כל הטיפים.
9. בסיום הארוחה, הטאבלט המאסטר סוגר את השולחן ("סגירת שולחן") — כל הסועדים
   מקבלים הודעה שהשולחן נסגר, וסריקה הבאה של אותו QR תפתח session חדשה.

## הרחבות אפשריות

- אימות/PIN לטאבלט המאסטר כדי שלא כל אחד יוכל לפתוח אותו.
- הדפסת/שליחת חשבון בסיום.
- תשלום מהנייד.
- ריבוי מסעדות/סניפים.
